# DART 공시 리서치 에이전트 — 평가 시스템

> 단테의 From Scratch #2 실전 8 · AI 평가(23\~34편) 결과를 한 장으로. 숫자는 모두 이 저장소의 실행 기록에서 나왔다(2026-10-19, deepseek-v4-flash).

## 1. 문제
삼성전자 · SK하이닉스 · 현대자동차 · 카카오의 2025년 사업보고서로 답하는 리서치 에이전트(RAG + 멀티 에이전트 + MCP).
틀린 숫자, 공시에 없는 전망을 사실처럼 말하기, 투자 권유가 가장 위험하다 → 이 셋을 먼저 잰다.

## 3. 데이터셋 · 라벨
- 실행 기록 질문 127개 → 시험지 v2 67문항(개발 48 · held-out 19), 보고서형 12문항은 원래 문항 은행에 0개였다 (25편)
- 사람 라벨: 26편 메모 14개를 결정권자 한 명이 검토 · 승인, 지침 v1 = 루브릭 (30편)

## 4. 채점기 · 루브릭
- 루브릭 v1 예/아니오 기준 6개(R1\~R6), 코드 기준 모두 통과 40/53. 1\~5점은 같은 답에 2\~4점으로 흔들림 (27편)
- 코드 채점기 v3 · 테스트 12개, 사람 메모와 일치 51 → 53/53. 실행 채점 24/24(.pyc 캐시 버그를 찾아 고침) (28편)
- LLM 판사 v2: 넣은 거짓 문장 8/8 검출, 쌍 비교 순서 바꾸기 갈림 0/18 (29편)

## 5. 판사 검증
- 사람 라벨 14개(실패 5): 판사 v2 TPR 5/5(95% 57\~100%) · kappa 1.00 — dev 성적, 라벨러 1명 (30편)
- 일치율만 보면 속는다: "항상 통과"도 일치 77.4%, 하지만 TPR 0 · kappa 0

## 6. 통계
- 개발 48문항 81%(95% 70\~92%), 48문항으로 잡을 수 있는 최소 차이 17%p, pass^3 13/20 (31편)

## 7. 회귀 관문
- 회귀 세트 35(26편 정답 중 세 번 기록이 있으면 세 번 다 맞은 문항 — 한 번만 본 문항 중 3개가 34편에서 흔들림으로 드러남) · 능력 세트 18. 회귀는 문항 단위로 막는다 (33편)
- GitHub Actions 회귀 관문(저장된 출력 재채점 · 모델 호출 0 · 4\~5초): 실제 PR에서 회귀 5문항을 막음

## 8. 개선 한 바퀴 (34편)
- 오류 분석 → 가장 큰 칸(계획 6) → 한 곳 수정 → 영향받은 문항 + 회귀 세트만 다시 실행 → 관문
- 계획 담당 지시문 한 곳을 고쳐 계획 실패 6문항 0/6 → 5/6(95% 44%\~97%), 회귀 세트 32/35 — 관문 실패(n11 q35 q33)
- 다시 돌린 41문항 짝 비교: +5%p (95% -9%p \~ +18%p), 다시 돌리기 비용 $0.03

## 9. 한계
- 라벨러 한 명, 판사 검증은 dev 성적(손대지 않은 test 라벨 없음), 실패 라벨 5개라 구간이 넓다
- 문항이 적다(개발 48): 17%p보다 작은 차이는 평균으로 말할 수 없다
- 운영 트래픽이 없다: 온라인 신호는 26편 기록을 운영 로그라고 친 계산이다
- 개선 한 바퀴에서 능력 세트 나머지 12문항은 다시 돌리지 않았다(비용)
