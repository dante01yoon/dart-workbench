# 2편 과제 풀이 (실측 2026-10-11, deepseek-v4-pro)

## 과제 1 — 결과 칸을 연도로 (`solutions/a1_year_labels.py`)
```bash
uv run python sec02/solutions/a1_year_labels.py
```
배당 도구 결과의 `thstrm`·`frmtrm`·`lwfr`를 요청 연도 기준으로 `2025년`·`2024년`·`2023년`으로 바꿔 돌려준다.

| | 2023년 | 2024년 | 2025년 |
|---|---|---|---|
| 공시 (카카오 보통주 주당 현금배당금) | 61원 | 68원 | 75원 |
| 바꾸기 전 에이전트 답 | 60원 ✗ | 61원 ✗ | 75원 |
| 바꾼 뒤 에이전트 답 | 61원 | 68원 | 75원 |

- 도구는 맞게 불렀고 숫자도 결과 안에 있었다. 모델이 칸 이름을 잘못 읽었을 뿐이다.
- **도구 설명만큼 도구 결과도 설계 대상이다.** 약어 칸, 단위 없는 숫자, 기준 연도가 숨은 값은 모델이 틀리기 쉽다.

## 과제 2 — 헤매지 않게 (`solutions/a2_guard.py`)
```bash
uv run python sec02/solutions/a2_guard.py
```
- 같은 도구를 같은 인자로 다시 부르면 실행하지 않고 "이미 같은 인자로 불렀다, 다른 도구가 없으면 확인되지 않는다고 답하라"를 결과로 돌려준다.
- 도구 호출 상한 6: 넘으면 "지금까지의 결과로 답하라"를 돌려준다. 턴 상한 5: 넘으면 루프를 끝낸다.
- 시스템 프롬프트: 도구 결과로 답할 수 없으면 추측하지 말고 "공시 데이터로 확인되지 않음"이라고 답한다.

| | 통과율 | 토큰 | $/문항 | p50 | p95 |
|---|---|---|---|---|---|
| 2편 기본 (녹화) | 18/20 | 243,473 | 0.0036 | 12.9s | 290.6s |
| 과제 2 | 18/20 | 165,077 | 0.0025 | 12.9s | 83.7s |

- 통과율은 그대로다. 연구개발비 두 문항은 **답할 도구가 없어서** 여전히 틀린다. 달라진 건 틀리는 방식이다. 몇 분씩 헤매다 틀리는 대신, 80초 안에 "확인되지 않음"이라고 멈춘다.
- 그 결과 토큰은 32% 줄고, p95는 290초에서 84초로 줄었다.
- **채점 함정 하나.** 처음 돌렸을 때는 95%가 나왔다. 삼성전자 연구개발비 문항의 답에 "확인되지 않음"과 함께 다른 숫자들이 섞였는데, 그중 하나가 정답 문자열에 걸린 것이다. 정답 키를 "11.3"과 "줄었다/감소" 둘 다 있어야 통과로 고쳐서 다시 쟀다(위 표). 성적표 숫자가 갑자기 좋아지면 **틀린 문항의 답을 직접 열어 보자.**

## 과제 3 — 도구 하나 더: 증자·감자 현황 (`solutions/a3_irds.py`)
```bash
uv run python sec02/solutions/a3_irds.py
```
설명은 네 가지를 지킨다: 무엇을 돌려주나(날짜·형태·주식 종류·수량·액면가·발행가), 언제 쓰나(자기주식 취득·처분은 `treasury_stock`), 넣을 값(회사 4곳, 2024·2025), 결과 거르기(요청 연도만).

**처음 만든 버전은 틀린 답을 냈다.**
- 이 API는 최근 5년 치를 날짜 오름차순으로 돌려준다(카카오 69줄).
- `tools15.py`의 공통 규칙대로 앞 25줄만 자르면 2021~2022년만 남는다.
- 모델은 "2025년에는 증자·감자가 없다"고 자신 있게 답했다.

자르기 전에 요청 연도로 거르게 고친 뒤의 답:
- 2025년 증자: 주식매수선택권 행사 12건, 1,035,747주
- 2025년 감자: 4월 30일 무상감자 2,202,644주

공시 원본 값과 같다. 결과를 자를 때는 **무엇이 잘려 나가는지** 확인하자. 잘린 결과에는 `note: 앞 25줄만`이 붙지만, 모델은 그 표시를 보고도 "없다"고 답할 수 있다.
