# 26편 오류 분석 — 메모 달기 → 묶기 → 세기, 전이 실패 행렬

점수는 몇 개가 틀렸는지만 알려 줍니다. 무엇을 고칠지는 틀린 답 안에 있습니다. 개발 문항을 단계별 기록(트레이스)과 함께 돌리고, 사람이 읽고 메모를 단 뒤, 비슷한 실패끼리 묶어 셉니다.

## 파일
| 파일 | 내용 |
|---|---|
| `01_run.py` | 시험지 v2 개발 48문항 + 24편에서 틀린 5문항을 워크벤치로 돌리며 이벤트(계획 · 작업별 근거 수 · 작성 · 심판)를 모두 남긴다 → `data/traces26.jsonl`. 채점은 22편 채점기 그대로. held-out은 열지 않는다 |
| `02_memo.py` | 메모 화면(http://127.0.0.1:8829): 틀린 문항 먼저, 궤적 칸(근거 0개는 빨강), 한 줄 메모 + "처음 틀어진 단계"(에이전트 안 6단계 · 채점기 · 정답 키) → `data/memos26.json` |
| `03_group.py` | 메모만 모델에게 주고 유형 초안을 받는다(1번, 빈 답이면 한도를 늘려 다시). 유형별 개수 + 전이 실패 행렬(행: 마지막으로 잘 된 단계, 열: 처음 틀어진 단계) → `data/groups26.json` · http://127.0.0.1:8830 |
| `solutions/` | 과제 풀이(SOLUTIONS.md) |

## 실행
```bash
uv run python sec26/01_run.py        # 53문항, 약 31분 · 약 $0.35 (deepseek-v4-flash, 2026-10-19)
uv run python sec26/02_memo.py       # 브라우저에서 메모를 달고 「저장」
uv run python sec26/03_group.py      # 같은 메모면 저장된 묶음을 다시 쓴다
```

- 처음 틀어진 단계: 계획 6 · 공시 검색 5 · 채점기 1 · 재무 조회 1 · 작성 1.
- 모델이 묶은 유형(6개): 재무 도구 항목 부재 3 · 비공식 출처를 사실로 제시 3 · 검색 대상 · 내용 해석 오류 3 · 검색 · 추출 실패로 정보 누락 2 · 근거 없는 문장 생성 2 · 문제 없음 1. 사람이 확인해 두 곳을 고쳐 읽는다: n11은 "문제 없음"이 아니라 채점기 문제(정답 키 표기), q32는 검색이 아니라 계획에서 연도를 잘못 잡음.
- 전이 실패 행렬에서 가장 큰 칸: 시작 → 계획 6, 계획 → 공시 검색 3. 앞 단계(계획)부터 고친다.
- 다음 편으로 넘긴 것: "근거 없음"을 공시 기준으로 볼지(27편), 채점기 문제 2개(n11 · q54, 28편).

## 면접 질문
1. "실패 유형을 언제까지 찾아야 하나요?" → 새 기록을 읽어도 새 유형이 안 나오고 기존 유형도 안 바뀔 때까지(이론적 포화). 실무 가이드는 적어도 100개.
2. "다단계 에이전트에서 어느 단계부터 고치나요?" → 처음 틀어진 단계를 적고 전이 실패 행렬로 센다. 큰 칸, 앞쪽 단계부터.
3. "오류 분석을 모델에게 맡겨도 되나요?" → 묶기 초안은 맡겨도 된다. 메모와 처음 틀어진 단계는 사람이, 묶음도 사람이 확인한다.

## 과제
1. 맞았다고 채점된 답 중 수상한 것(뉴스 근거 · 심판 '부족' · 거절 문항에 보고서)을 골라 읽는다.
2. 메모를 하나씩 더할 때 유형 수가 어떻게 늘어나는지(포화 곡선) 그린다.
3. 처음 틀어진 단계를 문항 출처별(13편 문항 · 실행 기록 문항 · 24편 실패)로 나눠 센다.
