# 24편 공개 벤치마크 읽는 법 — MMLU · SWE-bench · τ-bench, 그리고 오염

공개 벤치마크가 각각 무엇을 재는지 1차 출처(논문 · 공식 글)로 확인하고, GSM1k 방식(같은 난이도로 처음 보는 문항)을 우리 시험지에 그대로 해 봅니다.

## 파일
| 파일 | 내용 |
|---|---|
| `benchmarks.json` | MMLU · SWE-bench · SWE-bench Verified · τ-bench · GSM1k: 무엇을 재나 · 채점 · 규모 · 대표 숫자 · 한계 · 출처 url과 위치(2026-10-19 원문 확인) |
| `01_benchmarks.py` | 비교표 화면(http://127.0.0.1:8825). API 호출 없음 |
| `02_heldout_check.py` | 13~22편 내내 보던 개발 20문항 vs 같은 유형 비율로 고른 처음 보는 20문항을 같은 날 같은 워크벤치(deepseek-v4-flash)로 돌려 비교 → `data/heldout24.json` · `scorecard.jsonl` 두 줄 · 화면(http://127.0.0.1:8826). `--show`는 저장된 결과로 화면만 |
| `solutions/` | 과제 풀이(SOLUTIONS.md) |

## 실행
```bash
uv run python sec24/01_benchmarks.py
uv run python sec24/02_heldout_check.py          # 40문항 · 약 25분 · 약 $0.23(2026-10-19 기준)
uv run python sec24/02_heldout_check.py --show   # 다시 볼 때(API 호출 없음)
```

## 실제 결과 (2026-10-19 강의 녹화 실행, 모델 deepseek-v4-flash)
| | 개발 20(보던 문항) | 처음 보는 20 |
|---|---|---|
| 정답 | 18/20 (90%) | 15/20 (75%) |
| 문항당 비용 | $0.00523 | $0.00649 |
| p50 지연 | 82.0초 | 111.7초 |
- 유형별(개발 → 처음 보는): 숫자 4/4 · 4/4, 전년 대비 3/3 · 1/3, 회사 비교 3/3 · 2/3, 서술 4/4 · 2/3, 사실 2/2 · 3/3, 근거 없음 0/2 · 1/2, 투자 권유 2/2 · 2/2.
- 처음 보는 문항의 실패 5개를 열어 보니 채점기 탓이 아니었다: q32 연구개발비 근거를 못 찾음, q38 배당 비교에 매출 · 영업이익을 답함, q50 금융부문을 "확인되지 않음", q33 배당 증가를 "800원"(실제 3,000 − 2,204 = 796원)으로만 답함, q52 2026년 3분기 영업이익을 증권사 전망으로 답함.
- 개발 쪽 실패 2개(q51 2027 매출 전망 · q54 신차 출시일)는 둘 다 뉴스 속 전망으로 답했다. 22편 과제 1에서 남긴 질문 그대로다 — "근거 없음"을 공시 기준으로 볼지, 공시 + 뉴스 기준으로 볼지 정해야 한다(27편 루브릭).
- **같은 개발 20문항, 다른 날**: 22편(10/17) 19/20 · $0.0009/문항 → 오늘 18/20 · $0.0052/문항(약 5.8배). 모델 이름이 같아도 날이 다르면 숫자가 달라진다. 그래서 비교는 같은 날 같이 돌린다.
- 20문항씩이라 90%와 75%의 차이가 우연인지는 아직 말할 수 없다(31편 신뢰구간).
- 가장 오래 걸린 문항: q04(SK하이닉스 당기순이익) 929초.

## 면접 질문
1. "벤치마크 점수가 높은 모델이 우리 제품에서는 왜 못할 수 있나요?" → 재는 일과 채점이 우리 일과 다르다(객관식 지식 · 코드 테스트 ≠ 근거로 숫자 답하기). 공개 문항은 오염됐을 수 있다. 그래서 우리 데이터로 만든 평가가 따로 필요하다.
2. "평가 데이터 오염은 어떻게 알아내고 막나요?" → 같은 난이도로 처음 보는 문항을 새로 만들어 점수를 비교한다(GSM1k, 오늘 실습). held-out 세트를 잠가 두고 튜닝할 때 열지 않는다(25편).

## 과제
1. 처음 보는 문항을 개발 문항과 많이 닮은 것(유사도 0.5 이상)과 덜 닮은 것으로 나눠 정답률을 비교한다.
2. 틀린 문항을 열어 에이전트 탓인지 채점기 탓인지 나눈다.
3. 우리 평가 세트를 벤치마크 카드 한 줄로 설명해 비교표에 붙인다.
