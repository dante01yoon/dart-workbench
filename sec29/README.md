# 29편 LLM 판사와 루브릭 — 판사 지시문, 기준 하나에 판사 하나, 쌍 비교와 위치 바꾸기

27편 루브릭(채점 기준표)의 기준을 LLM 판사로 채점합니다. 27편에서 예/아니오 판사는 등기임원 9명 중 4명만 쓴 답(n07)에 5번 모두 "예"였습니다 — 흔들리지 않고 똑같이 틀렸습니다. 오늘은 판사 지시문을 고치고, 판사의 편향(위치 · 장황함)을 순서 바꾸기로 잽니다.
에이전트는 다시 돌리지 않습니다. 26편 실행 기록(`data/traces26.jsonl`)만 채점합니다.

**판사가 맞았는지는 정답을 아는 경우로만 확인합니다** — 코드 채점기(정답 키가 공시에서 나옴)와 일부러 만든 답(넣은 거짓 문장 · 뺀 문장 · 똑같은 답 · 늘인 답). 판사와 사람 라벨의 일치는 30편에서 다룹니다.

## 파일
| 파일 | 내용 |
|---|---|
| `judge.py` | 판사 v2 — 지시문 `prompt_v2`(기준 하나 · 통과/실패 예 · 정답 정보 또는 근거 · 이유 먼저), 비교용 `prompt_v1`(27편 그대로) · `prompt_all`(기준 6개를 한 번에), `ask`(빈 답이면 한도를 늘려 한 번 더). 예시는 채점할 문항과 겹치지 않게 새로 썼다 |
| `01_judge.py` | A. R2 빠짐없이 14문항: 27편 지시문 vs 판사 v2 → 코드 채점과 비교. B. R6 지어내지 않음: 깨끗한 답 8개 + 근거에 없는 문장을 하나 넣은 8개 → 기준 하나씩 vs 한 번에 → `data/judge29.json` · http://127.0.0.1:8835 (`--show`) |
| `02_pairwise.py` | 쌍 비교 · 위치 바꾸기: 26편 답 6개 × (빠짐 · 같은 답 · 장황) × 순서 2 → `data/pair29.json` · http://127.0.0.1:8836 (`--show`) |
| `solutions/` | 과제 풀이(SOLUTIONS.md) |

## 실제 결과 (2026-10-19 강의 녹화 실행, deepseek-v4-flash)
- A. R2 빠짐없이 — 코드 채점과 같은 판정: 27편 지시문 12/14 · 판사 v2 13/14.
  - n07(등기임원 4/9): 27편 지시문 "예"(27편과 같은 "똑같이 틀림") → 판사 v2 "아니오", 이유에 빠진 5명 이름.
  - n09(임원 보수): 판사 v2 "아니오"(안현 빠짐), 코드 "예" — 코드 R2는 첫 정답 항목을 R1(핵심 값) 몫으로 빼고 센다. 판사 오류가 아니라 기준을 나눈 방식 차이.
- B. R6 지어내지 않음 — 넣은 문장 8개 중 잡은 수: 기준 하나씩 8/8 · 한 번에 8/8.
  - 넣기 전 원본 8개에도 "아니오" 3개(q17 특수관계인 포함 지분율 · n10 감사위원회 교육 시기 · q49 세부 설명): 근거 요약(claim)에 없는 세부를 짚었다. 정답을 모르는 경우라 맞고 틀림을 말하지 않는다(사람 라벨 → 30편).
- 쌍 비교(18쌍 × 순서 2 = 36번): 순서를 바꿔 판정이 갈린 쌍 0/18. 빠짐 → 원래 답 12/12 · 같은 답 → 무승부 12/12 · 장황 → 원래 답 12/12.
  - 지시문에 루브릭이 있고 차이가 뚜렷한 쌍이라 편향이 안 보였다. 루브릭을 빼면 장황 쌍 1개가 순서에 따라 갈렸다(과제 3).
- 비용: 녹화 실행 96번 $0.0284(`lessons/sec08/COST.md`).

## 면접 질문
1. "LLM 판사의 편향은 무엇이 있고 어떻게 줄이나요?" → 위치 · 장황함 · 자기 선호. 순서를 바꿔 두 번 묻고 둘이 같을 때만 인정(갈리면 무승부), 루브릭과 정답 정보를 주고 이유를 먼저 쓰게 한다. 판사 자체는 사람 라벨로 검증한다.
2. "같은 모델로 답하고 채점해도 되나요?" → 자기 선호 편향 위험. 가능하면 다른 계열 모델을 판사로, 적어도 사람 라벨과의 일치로 확인한다. (이번 실습은 같은 Flash 모델 — 정답을 아는 경우로만 확인했다.)
3. "판사 지시문을 어떻게 설계하나요?" → 기준 하나에 판사 하나, 채점 문항과 겹치지 않는 통과 · 실패 예, 판단 재료(정답 정보 · 근거), 이유 먼저 판정 나중.

## 과제
1. 판사 v2에서 `[정답 정보]` 줄만 빼고(근거는 준다) R2 14문항을 다시 채점해 코드와 몇 개가 같은지 센다.
2. 보수적 집계(두 순서에서 같은 답을 골랐을 때만 승, 갈리면 무승부)를 `data/pair29.json`에 적용한다.
3. 쌍 비교 지시문에서 루브릭을 빼고 "어느 답이 더 좋은가?"만 물어 같은 답 · 장황 쌍을 다시 잰다.

참고: Zheng et al., [Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena](https://arxiv.org/abs/2306.05685) (NeurIPS 2023) — 위치 · 장황함 · 자기 선호 편향, 순서 바꾸기(보수적 집계), 참조 기반 판사(2026-10-19 확인).
