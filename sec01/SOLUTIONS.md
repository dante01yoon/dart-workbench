# 1편 과제 풀이 (실측 2026-10-11)

## 과제 1 — 모델 바꾸기
```bash
MODEL=anthropic/claude-haiku-5.5 uv run python sec01/03_harness.py
```
| 모델 | 통과율 | 토큰 | $/문항 | p50 | p95 |
|---|---|---|---|---|---|
| deepseek-v4-pro | 12/12 | 15,109 | 0.00017 | 18.3s | 21.6s |
| claude-haiku-5.5 | 12/12 | 16,723 | 0.00024 | 12.3s | 15.4s |

- 통과율은 같다. Haiku가 6초 빠르고, 문항당 비용은 약 40% 더 든다.
- "어느 모델이 좋다"는 정답은 없다. 빠른 답이 중요하면 Haiku, 비용이 중요하면 deepseek-v4-pro처럼 성적표의 칸을 보고 고른다.
- 같은 모델로 다시 돌려도 지연은 1~3초씩 흔들린다. 결론을 내기 전에 두세 번 돌려 보자.

## 과제 2 — 연도 비교 문항 더하기
```bash
uv run python sec01/03_harness.py "과제2 · 연도 비교 포함" number,year_compare
```
결과: 20문항 중 16개 통과(80%). 틀린 4문항:
- 삼성전자 연구개발비 비율은 전년보다 늘었나 줄었나?
- SK하이닉스 주당 배당금은 전년 대비 어떻게 바뀌었나?
- 현대자동차 주당 배당금은 전년 대비 어떻게 바뀌었나?
- 카카오 연구개발비용은 전년 대비 늘었나?

**원인:** 모델이 틀린 게 아니라 **도구가 없다**. `get_financials`는 매출액·영업이익·당기순이익만 돌려준다. 연구개발비·배당금은 다른 API(배당은 `alotMatter`, 연구개발은 사업보고서 본문)에 있다.
- 모델은 도구를 두 번 불렀지만 답할 재료가 없었다. 좋은 루프라도 도구가 모자라면 성적표에 그대로 드러난다.
- 매출·이익 연도 비교 4문항은 모두 맞혔다(도구를 2024·2025로 두 번 호출).
- → 2편에서 배당·임원·직원 등 OpenDART 도구를 15개로 늘린다.

## 과제 3 — 도구 설명 망가뜨리기 (`solutions/a3_bad_description.py`)
```bash
uv run python sec01/solutions/a3_bad_description.py
```
| 도구 설명 | 통과율 | $/문항 | p50 | p95 | 도구 2번 부른 문항 |
|---|---|---|---|---|---|
| 정상 (1편 기본) | 12/12 | 0.00017 | 18.3s | 21.6s | 0 |
| "데이터" + enum 제거 | 12/12 | 0.00023 | 18.7s | 32.3s | 2 |

- 통과율은 그대로다. 대신 모델이 회사 이름이나 연도를 한 번에 맞히지 못해 **도구를 다시 부른 문항**이 생겼다. 그만큼 느린 쪽 지연(p95)이 50% 늘었고, 비용도 35% 늘었다.
- 큰 모델은 나쁜 설명도 어떻게든 버티지만, 그 대가는 비용과 지연으로 낸다. 작은 모델에서는 통과율 자체가 떨어진다(2편에서 잰다).
