# 31편 통계 기초 — 신뢰구간 · 표본 크기 · 유의성, pass@k와 pass^k

면접 질문 "새 프롬프트가 2%p 올랐는데 진짜 개선인가요?"에 숫자로 답합니다. 정답률 하나에 "얼마나 흔들릴 수 있나"(신뢰구간)를 붙이고, 같은 문항으로 잰 두 점수는 짝 비교로 봅니다. 몇 문항이 있어야 차이를 믿을 수 있는지 계산하고, 같은 문항을 여러 번 시킨 기록으로 pass@k와 pass^k를 셉니다.
**모델 호출은 없습니다.** 24 · 26편 실행 기록과 10/18 세 번 돌리기 기록만 다시 셉니다. held-out 19문항은 열지 않습니다.

## 실제 결과 (2026-10-19 강의 녹화 실행)
- 개발 48문항(26편): 39/48 = 81%, 표준오차 5.6%p → 95% 신뢰구간 70.2 ~ 92.3%, 부트스트랩 68.8 ~ 91.7%. 한 문항 = 2.1%p — **"2%p 올랐다"는 한 문항 더 맞혔다는 뜻**이다.
- 24편 보던 20 90% vs 처음 보는 20 75%: 차이 +15%p, 다른 문항이라 짝이 없다 → 95% 신뢰구간 −8.1 ~ +38.1%p, 0을 포함(우연인지 아직 모른다).
- held-out 19문항(열지 않음): 정답률이 80%라면 ±18%p — 작은 개선을 재는 용도가 아니다.
- 같은 20문항 × 3회 = 답 60개: 따로 세면 표준오차 5.3%p, 문항으로 묶으면 7.2%p.
- 같은 시스템 세 번(10/18, 그날 채점기 v2): 18 · 16 · 13 / 20. 짝 비교 표준오차가 짝 무시보다 작다(2회 − 3회 13.9 → 8.2%p, 문항 상관 0.68). 1회 − 3회 +25%p는 짝 비교로도 0 밖 — 아무것도 안 바꿨는데. 3회차 답을 열면 빈 답 1개(q47)와 채점기가 놓친 거절 2개(q51 · q54) — 과제 2.
- 같은 날 같은 20문항 두 번(24편 → 26편): 90% vs 95%, 짝 무시 SE 8.3%p → 짝 비교 5.0%p(상관 0.69).
- 문항 수(짝 비교 · 유의수준 5% · 검정력 80%, 문항별 차이 분산 0.177): 5%p를 잡으려면 556문항, 2%p면 3,477문항. 48문항으로 잡을 수 있는 가장 작은 차이는 17%p.
- pass@k vs pass^k(같은 20문항 × 3회, 그날 코드 채점기 v2): pass@1 78.3%, pass@3 95.0%(19/20) · pass^3 65.0%(13/20). 독립이라면 0.783³ = 48.1% — 실제가 더 높다(실패가 q56 같은 몇 문항에 몰림). 사람이 읽은 대로(놓친 거절 3개 정정) pass^3 15/20 · pass@3 19/20.
- 비용: $0(모델 호출 없음).

## 면접 질문
1. "새 프롬프트가 2%p 올랐는데 진짜 개선인가요?" → 점수마다 표준오차와 95% 신뢰구간을 붙인다. 같은 문항이면 문항별 차이로 짝 비교한다(짝 무시보다 표준오차가 작다). 차이의 신뢰구간이 0을 포함하면 "아직 모른다". 우리 48문항에서 2%p는 한 문항이고, 잡을 수 있는 가장 작은 차이는 17%p다. 차이가 이상하게 크면 먼저 답을 연다(채점기 · 빈 답).
2. "문항이 몇 개 있어야 차이를 믿을 수 있나요?" → 검정력 분석: n = (z_α/2 + z_β)² · Var(차이) / δ². 우리 기록으로 5%p는 약 560문항. 큰 차이는 20~50문항으로 보이고, 작은 차이는 수백~수천 문항이 든다. 문항을 못 늘리면 같은 문항을 여러 번 돌려 평균을 쓰고(재샘플링), 묶인 문항은 군집 표준오차로 잰다.
3. "pass@k와 pass^k는 언제 쓰나요?" → pass@k는 한 번이라도 성공하면 되는 도구(코드 후보 여러 개 중 하나), pass^k는 매번 성공해야 하는 고객용 에이전트. 문항마다 성공률이 달라서 평균의 k제곱으로 짐작하지 말고 문항별로 센다.

## 과제
1. 개발 48문항을 회사로 묶어 군집 표준오차를 재고, 왜 보통 표준오차보다 작게 나오는지 설명한다.
2. 채점기가 놓친 거절 답 3개를 사람이 읽은 대로 고쳐 1 · 2 · 3회 짝 비교와 pass^3을 다시 잰다.
3. 두 버전의 문항 점수 상관이 0 · 0.3 · 0.5 · 0.7일 때 5%p 차이를 잡는 데 필요한 문항 수를 계산한다.
