# 6편 스킬과 서브에이전트 — 필요한 것만 메인 컨텍스트에

## 파일
| 파일 | 내용 |
|---|---|
| `skills.py` | 공용: `skills/*/SKILL.md` 읽기, 큰 스킬 부록(실제 공시 응답 예시), `load_skill` 도구, 한 턴에 도구 하나만 실행하는 루프(5편과 같은 강제), 완료 확인(`check`) |
| `01_skills.py` | 과제 8개 × {작은·큰 스킬} × {전부 넣기·점진적 노출} → `data/skills_runs.json` |
| `02_subagent.py` | 4개사 2025년 배당 점검 + 비교표: 메인 혼자 vs 서브에이전트에게 맡기기 → `data/subagent_runs.json` |
| `03_bars.py` | 메인 vs 서브 토큰 막대 http://127.0.0.1:8804 |

## 실행
```bash
uv run python sec06/01_skills.py
uv run python sec06/02_subagent.py
uv run python sec06/03_bars.py
```
모델은 `deepseek/deepseek-v4-flash`. 01은 약 8분·$0.30(큰 스킬 전부 넣기가 대부분), 02는 약 3분·$0.02.

## 실제 결과 (2026-10-12 강의 녹화 실행)
### 스킬 (과제 8개)
| 설정 | 지시 준수 | 맞는 스킬 읽음 | 과제당 입력 | 비용 |
|---|---|---|---|---|
| 작은 스킬(8개 합계 2,293자) · 전부 | 7/8 | – | 8,915 | $0.021 |
| 작은 스킬 · 점진적 | 6/8 | 8/8 | 9,921 | $0.018 |
| 큰 스킬(부록 포함 약 6만 자) · 전부 | 7/8 | – | 70,705 | $0.230 |
| 큰 스킬 · 점진적 | 6/8 | 7/8 | 16,942 | $0.027 |

- 스킬이 작으면 점진적 노출이 오히려 토큰을 더 쓴다. 스킬을 읽으러 가는 턴이 하나 더 생기기 때문이다.
- 스킬이 크면 점진적 노출이 토큰 4분의 1, 비용 8분의 1이다.
- 지시 준수 실패: 표식 앞에 `#`·`##`를 붙이거나, 표식 없이 설명부터 시작하거나, 빈 답(삼성전자 인력 현황, 큰 스킬 두 방식 모두). `**굵게**`만 감싼 것은 따른 것으로 채점한다(처음엔 이것도 실패로 셌다가 답을 열어 보고 고쳤다).

### 서브에이전트 (4개사 배당 점검)
| 실행 | 방식 | 주당배당금 | 메인 입력(최대) | 서브 입력 | 합계 | 비용 | 시간 |
|---|---|---|---|---|---|---|---|
| 첫 번째(완료 확인 없음) | 혼자 | 4/4 | 12,819 (4,257) | 0 | 12,819 | $0.009 | 62초 |
| | 서브에이전트 | **0/4** | 1,970 (806) | 4,930 | 6,900 | $0.003 | 59초 |
| 두 번째(완료 확인 추가) | 혼자 | 4/4 | 12,950 (4,292) | 0 | 12,950 | $0.007 | 52초 |
| | 서브에이전트 | 4/4 | 4,475 (1,293) | 9,662 | 14,137 | $0.014 | 122초 |

- 첫 번째 실행에서 메인이 두 회사만 맡기고 빈 답으로 끝났다. 같은 코드를 세 번 더 돌리면 세 번 다 4/4였다. 가끔 일을 덜 끝내고 멈춘다.
- 그래서 하네스에 **완료 확인**을 붙였다. 모델이 끝났다고 하면 맡기지 않은 회사가 남았는지, 답이 비었는지 보고, 남았으면 "아직 남았다"는 말을 보내 이어 시킨다(`CHECK = True`).
- 서브에이전트는 메인 대화를 3분의 1로 가볍게 한다. 대신 합계 토큰은 조금 많고 시간은 두 배 넘게 걸린다.
