# 25편 트레이스와 시험지 — 실행 기록에서 대표성 있는 평가 세트 만들기

20문항 시험지를 실제로 던진 질문(실행 기록)으로 키워 67문항 시험지 v2를 만들고, 개발(dev)과 held-out을 나눕니다.
모델은 부르지 않습니다. 정답은 OpenDART 공시 API에서 바로 뽑습니다(무료, `DART_API_KEY` 필요).

## 파일
| 파일 | 내용 |
|---|---|
| `01_collect.py` | 실행 기록(6편 스킬 · 12편 리서치 팀 · 16편 도구 실험 · 20편 반성 비교)에서 질문을 꺼내 겹치는 것을 빼고, 60문항 은행에 이미 있는지 "회사 · 연도 · 항목"으로 확인 → `data/sec25_candidates.json` |
| `02_gold.py` | 새 질문마다 공시 API로 정답 키를 붙인다. 정답이 하나로 안 정해지는 질문은 이유와 함께 뺀다. 기록의 모양만 빌린 새 문항 14개와 함정 5개를 더한다 → `data/sec25_gold.json` |
| `03_build_set.py` | 개발 · held-out 나누기, 같은 질문(twin) 검사, 화면(http://127.0.0.1:8827) → `eval/questions_v2.jsonl` |
| `solutions/` | 과제 풀이(SOLUTIONS.md) |

## 실행
```bash
uv run python sec25/01_collect.py
uv run python sec25/02_gold.py          # OpenDART 약 60번 호출(무료)
uv run python sec25/03_build_set.py     # Ctrl+C로 끝
```

## 나누는 규칙
- **개발(dev)**: 개발하면서 이미 돌려 보고 고친 문항 — 13편부터 보던 20문항 + 실행 기록에서 온 질문(16편 과제 1은 이 질문들로 도구 설명을 고쳤다).
- **held-out**: 아무도 돌려 본 적 없는 문항 — 기록의 모양만 빌려 회사 · 항목을 바꾼 새 문항, 함정, 은행에서 아직 안 쓴 문항.
- **넣지 않음**: 24편에서 돌려 본 20문항(개발 20문항과 같은 틀의 템플릿 — 대표성을 위해 뺌).
- **같은 질문(twin)**: 회사 · 연도 · 항목이 같거나, 회사와 정답 키가 같고, 기대하는 행동(답 · 거절)도 같으면 같은 질문. 기록 속 같은 질문은 하나만 남기고, held-out 후보가 개발 문항과 같으면 개발로 옮긴다.

## 실제 결과 (2026-10-19 강의 녹화 실행)
- 실행 기록 속 질문 127번 → 겹치는 것 빼면 34개 → 은행에 이미 있음 3개(q03 · q21 · q17) · 새 질문 31개.
- 정답 붙임 45개(기록 31 + 새 문항 14) · 뺌 5개: 현대자동차 직원 평균 연봉(남녀별 평균만 공시), 삼성전자 공시 목록(날마다 늘어남), SK하이닉스 현금흐름표 재고자산 변동(그 이름의 줄이 없음), 삼성전자 자사주 정책(기준이 사람마다 다름 → 27편 루브릭), 현대자동차 비교표(무엇을 비교할지 없음 → 되물어야 함).
- 정답을 붙인 실행 기록 질문 26개 중 **보고서형 12개** — 원래 60문항 은행에는 0개였다(대표성이 어긋난 자리).
- 기록 속 같은 질문 3개를 하나로: 삼성 · SK 영업이익과 메모리 위험 비교, 현대 매출과 관세 위험, SK 임원 보수 정리.
- held-out 후보 → 개발로 옮김 4개: 삼성전자 영업손실 이유(= q01), 하이닉스 작년 영업이익(= q03), SK하이닉스 대표이사(= 기록의 지배구조 정리와 정답 같음), 삼성전자 직원 수(= 기록의 인력 현황 정리와 정답 같음).
- **시험지 v2 67문항 = 개발 47 + held-out 20**, 마지막 검사에서 held-out ↔ 개발 같은 질문 0개.
  - held-out 20: 기록의 모양을 빌린 새 문항 12 · 함정 3 · 은행에서 안 쓴 문항 5. 유형: 보고서형 7 · 숫자 3 · 사실 2 · 전년 대비 2 · 회사 비교 2 · 거절 2 · 함정 1 · 근거 없음 1 · 서술 0(과제 1).
- 과제 2 풀이에서 실행 기록을 전부 뒤져 보니 q35가 4편 기록에 이미 있었다 → 개발로 옮긴 `eval/questions_v2_locked.jsonl`(개발 48 + held-out 19)을 다음 편부터 쓴다.

## 면접 질문
1. "운영 트래픽에서 대표성 있는 평가 세트를 어떻게 만드나요?" → 기록에서 모으고 의미(회사 · 연도 · 항목)로 중복을 뺀다 → 유형 비율을 실제 질문에 맞춘다 → 정답은 원천 데이터에서, 정답이 하나가 아니면 빼거나 루브릭으로 → held-out은 기록의 모양만 빌려 새로 만들고, 함정 · 적대 문항을 더한다.
2. "튜닝에 쓴 문항이 시험에 새는 걸 어떻게 막나요?" → 개발하면서 돌려 보고 고친 문항은 개발용으로 → held-out은 글자가 아니라 의미로 개발 문항과 겹치는지 검사 → 실행 기록을 뒤져 이미 돌린 적 있는지 확인하고 잠가 둔다(지문) → 큰 결정 때만 연다.

## 과제
1. held-out에 없는 서술 문항 2개를 사업보고서 문단에서 새로 만든다.
2. held-out을 잠근다: 실행 기록을 전부 뒤져 이미 돌린 문항을 개발로 옮기고 지문(sha256)을 남긴다.
3. 시험지 v2 전체를 한 번 돌리면 얼마 · 몇 분이 들지 24편 실행 기록으로 미리 계산한다.
