# 4편 사업보고서 전체를 넣으면 — 원문 도구와 결과 상한

## 파일
| 파일 | 내용 |
|---|---|
| `report.py` | 공시 목록에서 사업보고서 접수번호를 찾고, 원문 ZIP(document.xml)을 받아 목차 단위로 나눈다. 표는 행마다 "칸 \| 칸" 한 줄. `data/reports/`에 저장 |
| `report_tools.py` | 원문 도구: `read_full_report`(전체) · `list_sections`(목차) · `read_section`(섹션, `CAP`자 상한 + `next_start`) · `find_in_report`(키워드 줄 20개) |
| `01_context.py` | 같은 질문 6개(연구개발비·사업부문)를 A 전부 넣기 · B 목차 + 섹션 통째 · C 목차 + 6천 자 상한 + 찾기로 비교 |
| `03_bars.py` | 턴별 컨텍스트 막대 http://127.0.0.1:8802 |

## 실행
```bash
uv run python sec04/report.py 카카오 2025
uv run python sec04/01_context.py
uv run python sec04/03_bars.py
```
모델은 `deepseek/deepseek-v4-flash`다. 입력 100만 토큰까지 받고 100만 토큰당 $0.03이라, 사업보고서 한 권(50만 토큰 안팎)을 통째로 넣는 실험도 문항당 2센트 안팎으로 할 수 있다. `MODEL=...`로 바꿀 수 있다.

## 사업보고서 크기 (2025년)
| 회사 | 목차 | 본문 |
|---|---|---|
| 삼성전자 | 135개 | 79만 자 |
| 현대자동차 | 147개 | 83만 자 |
| 카카오 | 159개 | 82만 자 |

가장 긴 섹션 하나가 3만~12만 자다(임원 현황, 연구개발실적 상세, 특수관계자 거래).

## 실제 결과 (2026-10-12 강의 녹화 실행, deepseek-v4-flash, 질문 6개)
| 방식 | 통과 | 합계 토큰 | 비용 | 문항당 |
|---|---|---|---|---|
| A 전부 넣기 | 6/6 | 3,172,187 | $0.096 | 29초 |
| B 목차 + 섹션 통째 | 6/6 | 244,382 | $0.011 | 19초 |
| C 목차 + 6천 자 상한 + 찾기 | 6/6 | 186,861 | $0.009 | 24초 |

- 이번 질문들은 세 방식 모두 맞혔다. 100만 토큰을 받는 모델이면 통째로 넣어도 답은 찾는다.
- 대신 A는 호출 한 번에 47만~57만 토큰을 읽는다. C보다 토큰이 17배다. 질문이 쌓이면 이 차이가 그대로 청구서가 된다.
- B는 큰 섹션을 통째로 받으면 한 턴에 4만 7천 토큰으로 튄다. C는 상한과 찾기로 가장 높은 턴도 1만 6천 토큰에 그친다.
- 실행마다 숫자는 조금씩 다르다. 10/11 사전 실측은 A 3,170,846 $0.146 · B 246,703 $0.012 · C 136,590 $0.006(셋 다 6/6)이었다. 토큰은 거의 같은데 A 비용이 다르다(그날 청구된 단가 차이, 원인은 확인하지 않음).
- 더 비싼 모델(deepseek-v4-pro, 100만 토큰당 $0.95)이면 A는 문항당 약 50센트다.

## 과제
1. `read_section` 상한(CAP)을 2,000 · 6,000 · 20,000자로 바꿔 통과와 토큰을 잰다.
2. 목차·섹션 없이 `find_in_report` 하나만 주면? 찾은 줄의 앞뒤 한 줄을 붙이면?
3. 방식 B·C에서 가장 비싼 문항을 찾고, 도구 호출 순서로 이유를 설명한다.
