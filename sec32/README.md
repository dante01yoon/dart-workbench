## 면접 질문
1. "에이전트는 최종 답만 보나요, 궤적까지 보나요?" → 최종 결과를 먼저 채점한다. 궤적은 순서를 하나로 박지 않고(Anthropic: 너무 깨지기 쉽다) 필요한 도구 · 인자 · 중복 · 단계 수처럼 꼭 필요한 것만 코드로 본다. 우리 기록에서도 맞은 답 2개가 잘못된 인자 · 중복 호출로 운 좋게 맞았다.
2. "RAG가 틀렸을 때 검색 문제인지 생성 문제인지 어떻게 나누나요?" → 정답 문서를 정해 검색부터 Recall@k · MRR로 잰다. 틀린 문항은 검색 → 근거 뽑기 → 작성 칸으로 나눠 처음 끊긴 칸을 고친다. 채점기가 틀렸을 수도 있으니 답도 연다(n11).
3. "레드팀은 어떻게 하나요?" → 공격 종류별 작은 세트(인젝션 · 미끼 · 범위 밖)와 통과 기준을 미리 정하고 실제로 돌린다. 어디서 막혔는지 단계별로 적고, 통과해도 더 센 공격(사실처럼 쓴 가짜 문장)을 더한다.

## 과제
1. 정답을 섹션 대신 문단(청크)으로 좁히고, 원래 정의의 Recall@k(정답 중 찾은 비율)로도 다시 잰다.
2. 성공 1건당 비용을 문항 유형별로, 반성한 문항과 안 한 문항으로 나눠 본다.
3. 지시가 아니라 사실처럼 쓴 가짜 문장을 문서에 넣어 레드팀을 다시 돌린다(방어 한 줄 `--guard`도 비교).
