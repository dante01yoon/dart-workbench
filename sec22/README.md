# 22편 배포와 최종 성적표 — 직접 만든 것 vs 프레임워크

## 파일
| 파일 | 내용 |
|---|---|
| `01_final_scorecard.py` | 13편 평가 20문항을 처음(1편 루프 v0) vs 지금(20편 워크벤치)으로 돌려 `data/scorecard.jsonl`에 두 줄. 모델은 둘 다 deepseek-v4-flash. 채점은 13편과 같다 |
| `02_scoreboard.py` | 1편 성적표 화면에 "출처 단 문장 · 심판 지지" 칸을 더해 띄운다(http://127.0.0.1:8800) |
| `remote_tools.py` | 워크벤치가 17편 배포 MCP 서버를 HTTP + 토큰으로 부른다(도구 이름 · 연도 · 숫자 모양 맞추기) |
| `serve.py` | 배포용 서버 하나: 21편 API + 빌드한 React 화면 + 접근 코드(쿠키) + 하루 리서치 30회 |
| `render.yaml` | Render 무료 웹 서비스(Blueprint). 키 · 토큰은 `sync: false`(대시보드에 직접), 접근 코드는 `generateValue` |
| `make_deploy.sh` | 배포 묶음(`../deploy-workbench`) 만들기: 코드 + 빌드한 화면 + 보고서 정보. `.env` · 검색 색인은 넣지 않는다 |
| `solutions/` | 과제 풀이(SOLUTIONS.md) |

## 실행
```bash
uv run python sec22/01_final_scorecard.py          # 약 12분 · 약 $0.02
uv run python sec22/02_scoreboard.py               # http://127.0.0.1:8800
npm --prefix sec21/web run build
export MCP_URL=https://<17편 배포 주소>/mcp ACCESS_CODE=<아무 값>
export MCP_TOKEN="$(grep '^MCP_TOKEN_REMOTE=' .env | cut -d= -f2-)"
uv run uvicorn serve:app --app-dir sec22 --port 8790 > data/serve22.log 2>&1 < /dev/null &
# 브라우저: http://127.0.0.1:8790/?code=<ACCESS_CODE>
```
- 배포: `zsh sec22/make_deploy.sh` → 묶음을 **비공개** 저장소에 올리고(보고서 본문이 들어 있다) Render에서 New → Blueprint. `OPENAI_API_KEY` · `MCP_TOKEN` 두 값만 대시보드에 넣는다.
- 서버가 `.env`를 읽는 코드가 있어서 Render에서는 시작할 때 빈 `.env`를 만든다(`touch .env`, 값은 환경 변수가 우선).

## 실제 결과 (2026-10-17 강의 녹화 실행)
| | 처음 · 1편 루프 v0 | 지금 · 워크벤치 |
|---|---|---|
| 정답 | 18/20 (90%) | 19/20 (95%) |
| 출처 단 문장 | 0/63 | 71/72 |
| 심판 지지 | 0/63 | 70/72 |
| 문항당 비용 | $0.00006 | $0.0009 |
| 지연 p50 / p95 | 19.4초 / 53.7초 | 103.4초 / 261.8초 |
- 유형별(처음 → 지금): 숫자 4/4 → 4/4 · 전년 대비 3/3 → 3/3 · 회사 비교 3/3 → 3/3 · 서술 3/4 → 4/4 · 사실 2/2 → 2/2 · 근거 없음 2/2 → 1/2 · 투자 권유 1/2 → 2/2.
- **정정(10/18):** 영상 녹화 때는 처음 루프를 15/20(75%)으로 채점했다. 채점기의 거절 문구 목록에 "제공할 수 없" · "제공해 드릴 수 없"이 빠져, 처음 루프가 제대로 거절한 q51 · q54 · q59가 오답 처리된 것이다. 문구를 넣고 저장된 답으로 다시 채점하면 18/20(90%)이다(API 호출 없음). 정답률 차이는 작고, 큰 차이는 출처(0/63 → 71/72)다.
- 처음 루프는 재무 도구 하나뿐인데 서술 · 사실 문제(본사 위치, 외환위험 정의 등)를 "맞혔다". 도구에 없는 내용을 모델 기억으로 채운 것이라 출처가 하나도 없다.
- 지금 틀린 하나(q51 "삼성전자 2027년 매출 전망치")는 2025년 숫자 세 문장으로 답했다. 문장이 모두 사실이라 심판은 지지 — 심판은 문장 ↔ 근거만 보고, 질문 ↔ 답은 보지 않는다(과제 1).
- 투자 권유 두 문항은 계획 단계에서 1.5초 · 3.2초 만에 거절.
- 배포용 서버(로컬, 원격 MCP): 메모리 약 115MB(색인 없음). 접근 코드 없이 `/api/research` → 401. 화면에서 현대자동차: 재무 근거 3(0.4초) · 공시 근거 3(32.5초), 심판 2/6 → 반성 1회(4문장 고침) → 6/6, 176.6초 · $0.0013.

## 과제
1. 심판에 "질문에 맞는 답인가" 기준을 더해 2027년 전망 문항을 다시 돌린다.
2. 하루 상한을 횟수 대신 실제로 쓴 금액으로 바꾼다.
3. 성적표에 내 질문 5개를 더해 처음과 지금을 다시 잰다.
