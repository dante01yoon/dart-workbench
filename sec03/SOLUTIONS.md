# 3편 과제 풀이 (실측 2026-10-11, qwen3.5-9b)

## 과제 1 — 도구 검색 k (`solutions/a1_top_k.py`)
```bash
uv run python sec03/solutions/a1_top_k.py
```
| k | 검색 재현율 | 정확도 | 입력 토큰 |
|---|---|---|---|
| 1 | 0.90 | 0.88 | 370 |
| 3 | 1.00 | 1.00 | 612 |
| 5 | 1.00 | 0.90 | 843 |
| 8 | 1.00 | 0.98 | 1,114 |

- k=1이면 정답 도구가 검색에서 빠지는 질문이 생긴다(재현율 0.90). 검색이 놓친 도구는 모델이 아무리 똑똑해도 고를 수 없다.
- k=3부터 재현율 1.00. 그 위로는 토큰만 늘어난다.
- k=5의 0.90은 같은 설정의 `01_count.py`(0.98~1.00)보다 낮다. 작은 모델은 이 정도로 흔들린다. k를 고를 때는 정확도보다 **재현율과 토큰**을 먼저 보고, 여유를 두어 3~5를 고르자.

## 과제 2 — 헷갈리는 도구의 설명 고치기 (`solutions/a2_descriptions.py`)
```bash
uv run python sec03/solutions/a2_descriptions.py
```
세 도구에 "언제 쓰나 · 언제 쓰지 않나"를 더했다.
- `key_accounts`: 매출액·영업이익·자산총계 같은 대표 숫자를 물으면 **가장 먼저** 쓴다.
- `financial_ratios`: 비율(%)만. 금액이 필요하면 `key_accounts`.
- `all_financial_statements`: `key_accounts`에 없는 세부 계정일 **때만**.

| | 전체 정확도 | 재무 세 도구 문항 |
|---|---|---|
| 15개 · 원래 설명 | 0.93 | 15/18 |
| 15개 · 고친 설명 | 1.00 | 18/18 |
| 40개 · 원래 설명 | 0.92 | 15/18 |
| 40개 · 고친 설명 | 0.95 | 18/18 |

- 헷갈리던 재무 문항은 모두 맞혔다. 40개에서 남은 오답은 미끼 쪽(`employee_reviews`, `ipo_calendar`)이다.
- 도구 설명에 **다른 도구 이름을 적어 길을 알려 주는 것**이 짝끼리 헷갈릴 때 가장 잘 듣는다.

## 과제 3 — 도구별 캐시 유효기간 (`solutions/a3_ttl.py`)
```bash
uv run python sec03/solutions/a3_ttl.py
```
```
처음 조회         → 실제 호출: ['list_filings', 'key_accounts']
바로 다시 조회    → 실제 호출: []
이틀 뒤 다시 조회 → 실제 호출: ['list_filings']
```
- `TTL = {"list_filings": 24 * 3600}`: 공시 목록만 하루가 지나면 다시 조회한다. 사업보고서의 숫자는 정정 공시가 아니면 바뀌지 않으니 영구 저장한다.
- 이틀이 지난 상황은 저장 파일의 시각을 돌려 흉내 냈다(`os.utime`).
- 정정 공시까지 챙기려면 `list_filings` 결과에 "[기재정정]" 보고서가 새로 보일 때 그 회사의 캐시를 지우면 된다.
