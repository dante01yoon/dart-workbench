# 3편 도구가 많아지면 — 도구 40개, 도구 검색, 캐시와 호출 한도

## 파일
| 파일 | 내용 |
|---|---|
| `tools40.py` | 2편 도구 15개 + 실제 도구 3개(증자·감자, 주식 수, 타법인 출자) + 미끼 22개(주가·ESG·환율 등, 이 환경에 연결되지 않음) |
| `tool_search.py` | 도구 검색: 질문과 도구 이름·설명을 한국어 bigram BM25로 맞춰 가까운 k개만 고른다 |
| `select_lab.py` | 실험 공통: 질문 20개, `pick()`(모델에게 도구 하나를 고르게 한다) |
| `01_count.py` | 도구 3 · 15 · 40개 · 40개 + 도구 검색 5개일 때 정확도와 호출 한 번의 입력 토큰 (질문 20개 × 3번) |
| `02_search_agent.py` | 에이전트가 `find_tools`로 필요한 도구를 직접 찾아 붙인다. `--all`이면 40개를 처음부터 다 보여 준다 |
| `03_cache.py` | 같은 도구·같은 인자 결과를 디스크에 저장, 하루 호출 수를 세어 한도(OpenDART status 020) 전에 멈춘다 |
| `04_graph.py` | 도구 수 그래프 http://127.0.0.1:8801 |

## 실행
```bash
uv run python sec03/01_count.py
uv run python sec03/04_graph.py
uv run python sec03/02_search_agent.py
uv run python sec03/02_search_agent.py --all
uv run python sec03/03_cache.py
DAILY_LIMIT=0 uv run python sec03/03_cache.py "SK하이닉스 2025년 직원 수는?"
```

## 실제 결과 (2026-10-11, 녹화 포함 세 번 돌린 값)
| 설정 | qwen3.5-9b 정확도 · 입력 토큰 | claude-haiku-5.5 정확도 · 입력 토큰 |
|---|---|---|
| 3개 | 1.00 · 612 | 1.00 · 936 |
| 15개 | 0.93~0.97 · 2,185 | 1.00 · 2,978 |
| 40개 (미끼 22개) | 0.92~0.98 · 4,562 | 1.00 · 5,970 |
| 40개 + 도구 검색 5개 | 0.93~1.00 · 843 | 1.00 · 1,234 |

- **도구가 늘면 먼저 돈이 샌다.** 큰 모델은 미끼 40개에도 정확도가 그대로지만, 호출할 때마다 도구 설명을 다 읽으니 입력 토큰이 3개일 때의 6배를 넘는다.
- 작은 모델은 비슷한 이름에 걸린다: 직원 평균 연봉 → `employee_reviews`, 대표이사 → `ipo_calendar`, 자산총계 → `company_info`.
- 도구 검색으로 5개만 보여 주면 입력 토큰이 80% 넘게 준다. 검색 안에 정답 도구가 든 비율은 20문항 모두 1.00이다.
- 그런데 작은 모델의 정확도는 실행마다 다르다. 녹화 때는 검색 쪽이 0.93으로 오히려 낮았다. 틀린 셋은 도구를 아예 부르지 않은 경우였다.
- 3번 반복해 평균을 내도 0.03~0.07씩 흔들린다. 결론은 숫자 하나가 아니라 범위로 읽고, 흔들리지 않는 토큰 수부터 보자.

**에이전트가 도구를 찾게 하면** (질문: "카카오 2025년 배당성향이랑 직원 1인 평균 급여 알려줘", deepseek-v4-pro)
| | 모델 호출 | 합계 토큰 | 비용 |
|---|---|---|---|
| 40개 다 보여 주기 | 2번 | 10,902 ~ 11,153 | $0.0033 ~ 0.0044 |
| `find_tools`로 찾아 붙이기 | 3번 | 4,951 ~ 5,731 | $0.0027 ~ 0.0030 |

토큰은 절반 아래로 줄지만, 찾는 턴이 하나 늘어난다. 도구가 적으면 다 보여 주는 편이 빠르고, 많아질수록 검색이 이득이다.

**캐시** (같은 질문 4개를 두 번)
- 1회차: OpenDART 실제 호출 4번, 도구 시간 5.4~5.6초, 전체 49~57초
- 2회차: 실제 호출 0번, 캐시 4번, 도구 시간 0초, 전체 43~51초

캐시는 호출 한도와 도구 시간을 지켜 준다. 그래도 전체 시간의 대부분은 모델이 쓴다. 모델 쪽 비용·지연은 5편(프롬프트 캐시)에서 다룬다.
- `DAILY_LIMIT=0`이면 실제 조회 대신 "한도에 닿았다"는 결과가 모델에게 가고, 모델은 추측하지 않고 그 사실을 답한다.

## 과제
1. 도구 검색으로 몇 개를 보여 줄까? k = 1 · 3 · 5 · 8로 검색 재현율·정확도·입력 토큰을 잰다.
2. 작은 모델이 헷갈린 재무 도구 세 개(`key_accounts`·`financial_ratios`·`all_financial_statements`)의 설명에 "언제 쓰나 · 언제 쓰지 않나"를 더하고 다시 잰다.
3. 캐시에 도구별 유효기간을 둔다. 사업보고서의 숫자는 영구 저장, 공시 목록은 하루가 지나면 다시 조회한다.
