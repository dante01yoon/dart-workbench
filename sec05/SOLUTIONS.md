# 5편 과제 풀이 (실측 2026-10-12, deepseek-v4-flash)

## 과제 1 — 요약 기준 (`solutions/a1_threshold.py`, compact+todo)
| THRESHOLD | 정답 | 턴 | 총 입력 | 최대 입력 | 비용 |
|---|---|---|---|---|---|
| 3,000 | 24/24 | 42 | 94,302 | 3,651 | $0.234 |
| 6,000 (본편) | 24/24 | 17 | 63,506 | 6,835 | $0.037 |
| 12,000 | 24/24 | 18 | 109,218 | 13,022 | $0.044 |

- 기준을 너무 낮추면(3천) 거의 매 턴 요약한다. 요약 호출이 쌓여 비용이 6배로 뛰고, 턴도 42번으로 늘었다.
- 기준을 높이면(1만 2천) 요약은 덜 하지만 한 번에 보내는 입력과 총 입력이 커진다.
- 기준은 "요약 비용"과 "쌓인 기록을 다시 읽는 비용" 사이의 저울이다. 재 보고 고른다.

## 과제 2 — 덜 남기기 (`solutions/a2_clear_keep.py`)
| 설정 | 정답 | 턴 | 총 입력 | 최대 입력 | 비용 |
|---|---|---|---|---|---|
| KEEP=3 + 메모 (본편) | 24/24 | 44 | 296,610 | 10,004 | $0.124 |
| KEEP=1 + 메모 | 24/24 | 38 | 146,905 | 6,185 | $0.050 |
| KEEP=1 · 메모 없음 | 24/24 | 37 | 139,364 | 6,580 | $0.097 |

- 이번 실행에서는 세 설정 모두 24칸을 맞혔다. 턴이 37~44번으로 도구 호출 16번보다 훨씬 많다. 지워진 값을 다시 조회하거나 메모하는 데 턴을 쓴 것으로 보인다(호출 순서는 저장하지 않아 확인하지 않음).
- 메모가 없으면 토큰은 비슷해도 비용이 두 배다. 한 번 돌린 결과라 다시 돌리면 흔들릴 수 있다(지우기 방식은 실행마다 턴 수가 크게 다르다).

## 과제 3 — 요약의 값 (`solutions/a3_summary_cost.py`, 본편 녹화 실행의 data/long_task.json)
```
none          총 $0.0703 = 에이전트 호출 $0.0703 + 요약 호출 $0.0000  (17턴, 총 입력 175,431)
clear         총 $0.1238 = 에이전트 호출 $0.1238 + 요약 호출 $0.0000  (44턴, 총 입력 296,610)
compact       총 $0.0369 = 에이전트 호출 $0.0123 + 요약 호출 $0.0246  (19턴, 총 입력 69,169)
compact+todo  총 $0.0373 = 에이전트 호출 $0.0131 + 요약 호출 $0.0242  (17턴, 총 입력 63,506)
```
- 요약 방식의 에이전트 호출은 1.2~1.3센트로 그대로(7센트)의 6분의 1이다. 그런데 요약 호출이 2.4~2.5센트로 비용의 3분의 2를 차지한다.
- 요약 호출은 기록(최대 10만 자)을 읽고 값 표를 처음부터 다시 쓴다. 요약 모델을 더 싼 모델로 바꾸거나 요약 횟수를 줄이는 것이 다음 개선점이다.
