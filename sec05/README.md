## 파일
| 파일 | 내용 |
|---|---|
| `01_long_task.py` | 4개사 × 2년마다 `dividends`·`key_accounts`를 불러(도구 호출 16번) 24칸 표를 채운다. 네 방식(그대로 · 지우기+메모 · 요약 압축 · 요약+할 일 목록)을 차례로 돌려 `data/long_task.json`에 저장 |

## 실행
```bash
uv run python sec05/01_long_task.py
uv run python sec05/02_saw.py
```
모델은 `deepseek/deepseek-v4-flash`다. 네 방식을 다 돌리면 20~25분, 약 $0.27 든다. `uv run python sec05/01_long_task.py compact+todo`처럼 방식을 골라 돌릴 수 있다.

## 하네스로 "한 번에 도구 하나" 강제하기
- 처음 돌렸을 때 그대로 방식이 **2턴** 만에 끝났다(입력 698 → 19,913 토큰). Flash가 도구 16개를 한 턴에 한꺼번에 불렀기 때문이다.
- 요청에 `parallel_tool_calls: false`를 넣었지만 Flash는 무시했다.
- 그래서 하네스에서 막는다. 모델이 여러 개를 불러도 **첫 번째 호출만 남기고** 나머지는 버린다(`m["tool_calls"] = m["tool_calls"][:1]`). 대화 기록에도 그 하나만 남으니 모델은 다음 턴에 다음 도구를 부른다.

## 실제 결과 (2026-10-12 강의 녹화 실행, deepseek-v4-flash)
| 방식 | 정답 | 턴 | 총 입력 | 최대 입력 | 비용 (요약 호출) |
|---|---|---|---|---|---|
| 그대로 | 24/24 | 17 | 175,431 | 20,144 | $0.070 |
| 지우기 + 메모 | 24/24 | 44 | 296,610 | 10,004 | $0.124 |
| 요약 압축 | 24/24 | 19 | 69,169 | 6,790 | $0.037 ($0.025) |
| 요약 + 할 일 목록 | 24/24 | 17 | **63,506** | 6,835 | $0.037 ($0.024) |

- 그대로는 턴마다 앞의 결과를 다시 보내 입력이 계단처럼 오른다. 마지막 호출 한 번이 2만 토큰이다.
- 지우기는 최대 입력을 1만 토큰으로 막았지만 턴이 44번으로 늘었다(도구 조회 16번 외에 메모를 적거나 다시 조회한 턴). 총 입력은 오히려 그대로보다 많다.
- 요약 두 방식은 6천 토큰을 넘을 때마다 뚝 떨어져 톱니 모양이 된다. 총 입력은 그대로의 40% 안팎이다. 대신 비용의 3분의 2가 요약 호출이다.
- 같은 코드의 직전 실측(녹화 전)은 그대로 17턴 175,415 · 지우기 24턴 130,994 · 요약 22턴 76,840 · 요약+할 일 17턴 65,410(모두 24/24)이었다. 지우기 방식의 턴 수가 실행마다 크게 흔들린다.

## 과제
1. 요약 기준 `THRESHOLD`를 3,000 · 12,000 토큰으로 바꿔 compact+todo의 턴과 비용을 잰다.
2. 지우기에서 남기는 결과(`KEEP`)를 1개로 줄이면? 메모 도구(`USE_NOTE`)까지 빼면?
3. 요약 압축의 비용을 에이전트 호출과 요약 호출로 나눠 본다.
