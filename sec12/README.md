# 12편 멀티 에이전트 — 기업 리서치 팀

## 파일
| 파일 | 내용 |
|---|---|
| `web.py` | 뉴스 검색(Tavily search · extract) + 캐시 `data/web_cache.json` (같은 기사로 비교) |
| `team.py` | 리서치 팀: planner → 공시 · 재무 · 뉴스 워커(병렬/순차) → writer. 워커는 `{claim, source, quote}`만 넘기고, quote가 원문에 글자 그대로 있는지 확인한다. 재무 워커는 LLM 없이 재무 API 숫자. 노력 규칙 + `MAX_TASKS=8`. 빈 답이면 한도를 늘려 한 번 더 |
| `single.py` | 비교 기준: 도구 3개(공시 검색 · 재무 API · 뉴스)를 직접 부르는 단일 에이전트(턴 상한 10, 한 턴에 도구 하나) |
| `01_team.py` | 팀 한 번: 시간 막대 · 인용 검사 · 보고서 |
| `02_compare.py` | 질문 3개 × 단일 · 순차 팀 · 병렬 팀 → `data/team_compare.json` |
| `03_timeline_web.py` | 타임라인 화면 http://127.0.0.1:8812 |

## 실행
```bash
uv run --group frameworks python sec12/01_team.py
uv run --group frameworks python sec12/02_compare.py
uv run --group frameworks python sec12/03_timeline_web.py
```
`.env`에 `TAVILY_API_KEY`가 필요하다. 02는 15분 안팎 걸린다.

## 개념 출처
- Anthropic, "How we built our multi-agent research system"(2025-06-13): 리드 + 서브에이전트 병렬, 내부 평가에서 단일보다 +90.2%, 토큰은 채팅의 약 15배(에이전트 하나는 약 4배), 노력 규칙.
- Cognition(Walden Yan), "Don't Build Multi-Agents"(2025-06-12): 맥락을 공유하라 · 행동에는 숨은 판단이 있다, 플래피 버드 예, 기본은 단일 에이전트.

## 실제 결과 (2026-10-13 강의 녹화 실행)
01: 현대자동차 실적 + 관세 뉴스 — planner 3.7초, 재무 2.4초, 뉴스 110초, writer 36초. 인용 원문 일치 7/7, $0.0021, 보고서 6문장 모두 근거 번호.

| 질문 | 단일 | 순차 팀 | 병렬 팀 |
|---|---|---|---|
| 카카오 영업이익 · 사업 부문 | 17초 · $0.0005 · 도구 2 | 170초 · $0.0054 · 인용 7/7 | 184초 · $0.0051 · 인용 3/3 |
| 삼성전자 vs SK하이닉스 실적 · 위험 | 67초 · $0.0041 · 도구 9 | 99초 · $0.0022 · 인용 14/14 | 82초 · $0.0023 · 인용 14/14 |
| 현대자동차 실적 · 관세 뉴스 | 30초 · $0.0011 · 도구 4 | 167초 · $0.0033 · 인용 7/7 | 86초 · $0.0023 · 인용 5/7 |

- 단일 에이전트가 세 질문 모두 가장 빨랐고, 두 질문에서 가장 쌌다. 팀은 writer(추론 모델)와 가장 느린 워커를 기다린다.
- 팀은 근거를 정해진 모양으로 모아 인용을 원문과 대조할 수 있었다. 단일 에이전트의 "(출처: …)"는 글로 적은 것이라 코드로 대조할 수 없다.
- 녹화 전 시험에서는 단일 에이전트가 비교 질문에서 턴 상한(10)에 걸려 답을 못 낸 적도 있다(과제 2).

## 과제
1. `MAX_TASKS`를 2 · 4 · 8로 바꿔 비교 질문의 시간 · 비용 · 근거를 잰다.
2. 단일 에이전트의 턴 상한을 10 → 20으로 늘린다.
3. 뉴스 검색 기간을 30 · 180 · 365일로 바꾼다.
