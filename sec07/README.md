# 7편 RAG 첫걸음 — 자르고, 숫자로 바꾸고, 찾아서 답하기

## 파일
| 파일 | 내용 |
|---|---|
| `rag.py` | 공용: 청크 나누기(표가 잘리면 캡션·단위·열 이름 줄을 다시 붙임), 임베딩 API, 벡터 저장소(numpy), 코사인 검색 + 회사·연도 필터, 검색 성적표 |
| `01_chunks.py` | 4개사 2025년 사업보고서 → 청크 → `data/rag/chunks.jsonl` |
| `02_embed.py` | 청크 → 벡터(1,536차원) → `data/rag/emb.npy` |
| `03_eval.py` | 검색 성적표: recall@5 · MRR@10 (2025년 문항 38개, LLM 없이 문자열 채점) |
| `04_rag.py` | 4편과 같은 질문 6개를 RAG(상위 5조각)로 답하고 정답·토큰을 잰다 |
| `05_qa_web.py` | 출처 링크 Q&A 화면 http://127.0.0.1:8807 (근거 조각마다 섹션 경로 + DART 원문 링크) |

## 실행
```bash
uv run python sec07/01_chunks.py
uv run python sec07/02_embed.py
uv run python sec07/03_eval.py
uv run python sec07/04_rag.py
uv run python sec07/05_qa_web.py
```
임베딩은 `openai/text-embedding-3-small`(약 $0.05), 답변은 Flash. 처음 실행하면 사업보고서 원문 4권을 받느라 몇 분 걸린다(4편 `report.py`를 그대로 쓰고, 받은 원문은 `data/reports/`에 저장).

### 벡터 저장소를 numpy 파일로 둔 이유
실무에서는 pgvector 같은 벡터 DB에 넣는다. 이 편은 원리를 보려고 `emb.npy` 한 파일(3,948 × 1,536, 24MB)에 저장하고, 검색은 "정규화한 벡터의 내적 = 코사인 유사도"로 직접 계산한다. 설치할 것이 없다.

## 실제 결과 (2026-10-12 강의 녹화 실행)
- 청크 3,948개(평균 800자 남짓), 임베딩 2,612,468토큰 · $0.0522 · 59초
- 검색 성적표(벡터, 38문항): 필터 없음 recall@5 **0.447** · MRR@10 0.305 / 회사·연도 필터 **0.474** · 0.352
  - "연결 영업이익" 같은 숫자 질문에 "타법인출자 현황" 같은 숫자 표가 1위로 올라온다.
- RAG 답변(4편 질문 6개): **3/6** · 입력 16,925토큰 · $0.0019. 4편 전부 넣기(녹화)는 3,172,187토큰 · $0.096 · 6/6.
  - 현대차 매출 대비 연구개발비 비율, 삼성전자 연구개발비 비율 증감: 정답 조각이 상위 5개에 없었다(검색 실패).
  - 삼성전자 연구개발비용: 근거는 있었다. 다시 돌려 답을 열어 보니 총계 37조 7,548억을 답했고, 정답 키는 정부보조금을 뺀 37조 7,404억이라 틀림으로 채점됐다.

## 함정: 빈 답
- 처음 `max_tokens`는 1,500이었다. Flash가 생각(reasoning)에 1,500토큰을 다 써서 **답이 빈 채** 끝나는 경우가 있었다(finish_reason = length). Q&A 화면 첫 시도가 이렇게 비었다.
- 한도를 6,000으로 올리고, 빈 답이 길이 초과로 끝나면 그 사실을 답 자리에 적게 고쳤다. 고친 뒤 04_rag.py는 3/6 · 16,846토큰으로 같았다.

## 과제
1. 청크 크기(`SIZE`)를 400 · 1,600자로 바꿔 recall@5를 잰다.
2. 근거 조각을 5개 → 10개로 늘리면 정답과 토큰이 어떻게 바뀌나?
3. 임베딩할 때 청크 앞에 "회사 연도 사업보고서 · 섹션 경로"를 붙이면?
